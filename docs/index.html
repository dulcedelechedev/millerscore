Notation. Performance. One project.

MillerScore
User Guide

MuseScore, but with a built-in DAW. Write the music in a score, shape its performance in the piano roll, and choose your sounds in one connected workspace.

This guide covers the Windows v0.1.x Early Access series. Features and compatibility are still developing. Keep backups and read the playback and external-media limits before starting important work.

01 · Get started

Install & update

Use the Windows 64-bit build from the official MillerScore itch.io page. Source archives on GitHub are for building the application; they are not a ready-to-run Windows installation.

Install with the itch app

  1. Install the itch app from itch.io.
  2. Sign in to the itch.io account that has access to MillerScore. If a download is tied to a purchase or download key, use the account associated with that access.
  3. Open MillerScore in the itch app, choose Install, and select its Windows build and installation folder.
  4. Launch MillerScore from the installed entry. Store your projects and audio outside the application installation folder.

The itch app manages its own authentication and checks for updates to its installed downloads. A browser ZIP download is a separate installation. See itch.io's download guide and update guide.

Install a ZIP manually

  1. Download the Windows ZIP from your itch.io download page.
  2. In File Explorer, use Extract All to unpack the entire archive into a new folder.
  3. Open the extracted folder and run MillerScore.exe. Keep the accompanying application folders and DLLs together. Do not launch an executable from inside the ZIP.
  4. Create or open a small score, save it, reopen it, and check audio before using your main projects.

To update a manual install, close MillerScore, back up your projects and media, then extract the newer ZIP into a different folder. Launch the new copy and check a project copy before retiring the previous installation.

What the in-app update check does

Help > Check for update reads release information from the public GitHub Releases service. It does not sign in to itch.io or grant access to paid downloads. For releases delivered through itch.io, accepting the update opens the itch app's installation flow. If the itch link cannot open, the checker tries the official MillerScore itch.io page in your browser.

You still need the correct itch.io account and an available compatible download. A GitHub release announcement alone does not prove that an itch package has been uploaded. If an update cannot be fetched, open your itch library or download page directly.

Automatic checks can be turned off in Preferences > General > Updates. Background package downloads are off by default; the itch app has its own update settings.

02 · Hear your score

First launch & audio

  1. Create a short score with one instrument, or open a copy of an existing score.
  2. Open Edit > Preferences > Audio & MIDI.
  3. Choose an available Audio driver and Audio device. For recording, choose an ASIO driver with input channels.
  4. Choose a buffer size your device can sustain. If you hear crackles or dropouts, try a larger buffer; smaller buffers can reduce delay but require more reliable processing.
  5. Confirm a sound is assigned to the instrument, then press Play in the application's playback toolbar. Check the system output volume and your speakers or headphones.

Device and driver availability depends on Windows and your interface. A MIDI input or output selection is separate from the audio output. Connecting a MIDI keyboard does not itself install a sound library.

Start with a SoundFont. A working SoundFont assignment is a useful baseline when isolating a device, VST3, or optional Muse Sounds problem.

03 · One musical source

Score & DAW stay connected

Use the Score / DAW view switch above the document to change workspaces. The score supplies the notes, rhythm, parts, voices, ties, and written articulations. DAW tracks represent those score instruments. The piano roll shows the same score notes, with optional playback changes layered on top.

Notes mode

Edit the music itself: pitch, score position, written duration, and note creation or deletion. The notation changes with the edit.

Performance mode

Adjust how existing notes play: supported velocity, timing offsets, and sounding duration. The written score stays in place.

Choose the mode before dragging. A playback timing offset does not move the written note to a new beat. A sounding-duration override does not rewrite its notated duration.

Both views use the application's playback transport. Track and note selection connect the DAW to the score, and supported score and performance edits participate in project undo/redo. Save the native project to keep its performance data.

Keep the native project. Exported MIDI, MusicXML, PDFs, and audio serve different purposes. Do not assume they preserve every DAW override, controller curve, sound assignment, effect, or external clip reference.

04 · Shape the performance

Piano-roll editing

  1. Open DAW view and select a score instrument track. Its projected score notes appear in the piano roll.
  2. Choose Notes or Performance mode. Use the grid and Snap control for placement.
  3. Click a note to select it. Ctrl + click adds or removes a note; Shift + click selects a range in time. Select multiple tracks to see their notes together.
  4. In Notes mode, use the draw tool to create notes in the primary selected track. Drag to edit pitch or position, and resize to change written duration when the score permits the edit.
  5. In Performance mode, drag or resize existing notes to change playback timing or sounding duration. Use the control lane for a supported note property.
  6. Audition the change, use Undo if needed, then save and reopen a project copy to confirm the result.

The control selector includes dedicated note velocity, note fine pitch, channel pan, channel volume, and channel pitch lanes. Unavailable controls explain their limits in the selector. Note pan, release velocity, and per-note filter cutoff and resonance are currently unavailable.

Independent note velocity is available for SoundFont and compatible VST3 playback. It is disabled for Muse Sounds because its current playback interface does not expose independent velocity for simultaneous notes.

Complex notation still follows score-editing rules. Ties, grace notes, tuplets, and generated ornament playback need particular care; the piano roll is not a separate unlimited MIDI arrangement.

05 · Read the support labels

MIDI controllers: CC0 through CC127

The controller selector catalogs all 128 MIDI Control Change numbers with separate, stable lane identities. A controller value is a 7-bit integer from 0 to 127. Safe lanes can hold project automation points; protected stateful or channel-mode lanes are available for inspection but block edits.

Generic CC automation is sent only to MS Basic/SoundFont. The 108 editable numbered lanes send raw 7-bit values from 0 to 127 during main score playback. Use CC7 for volume, CC10 for pan, CC11 for expression, and CC64 for sustain; the audible response depends on the SoundFont instrument. Some controllers, including undefined numbers and LSB partners, may be ignored. Application WAV-export checks verify CC7, CC10, CC11, and CC64. The 20 protected lanes are never sent. Muse Sounds, VST3, and external MIDI output do not receive these generic lanes.

A CC11 lane replaces notation expression messages, and CC64/CC66 lanes replace notation sustain/sostenuto messages, on the corresponding channels while the lane is present. Note previews do not apply generic CC automation; use main playback to hear it. The dedicated Channel volume, Channel panning, and Channel pitch controls keep their separate playback paths.

Viewing a lane does not send its MIDI command. CC curves are scoped to the selected instrument track. Select the controller by its number as well as its name, edit its points, and use Undo/Redo for supported curve changes. Opening another lane must not be used as a reset or panic command.

Draw CC automation

  1. Open DAW and Piano Roll, select an instrument track, then choose a controller under Control, such as Common CC → CC7 — Channel Volume.
  2. Click the Pencil button beside Control. Click or drag in the lane below the notes to draw stepped points.
  3. Hold Alt while dragging to draw a continuous curve. Alt-drag also temporarily draws a curve with Pencil off.
  4. Release the mouse to apply the whole stroke. Ctrl+Z undoes it in one step; Esc cancels an unfinished stroke.

The stroke replaces existing points only inside its drawn time range. Points outside that range are retained. The timeline grid also applies to drawing; turn Snap off for finer freehand detail. Turn Pencil off to select and move points. Double-click empty space to add a point, or select a point and press Delete to remove it. Switching tracks or controllers cancels an unfinished stroke.

This gesture follows Logic Pro's documented Pencil behavior with the Option-for-curved setting, using Alt on Windows. See Apple's automation drawing guide. Bending an existing segment with Ctrl+Shift+drag is a separate gesture.

Understand a CC lane

Three diagrams to read a lane, follow its curve, and distinguish common controllers.

Categories & safety

Bank & program — protected

CC0 and CC32. Bank Select MSB/LSB choose a bank when combined with a separate Program Change message. Program Change is not a CC. Bank changes can select a different preset, so these stateful lanes are read-only until an ordered bank/program workflow is available.

Performance controllers

Modulation, breath, foot, portamento time, volume, balance, pan, expression, and their defined LSB partners. Their meaning is instrument-dependent. CC84 portamento control and CC88 high-resolution velocity prefix depend on a following note event, so their editing is protected.

General purpose

CC16–19, CC48–51, CC80–83. These can be assigned by a receiver. Their numbers do not guarantee a particular knob or audible function.

Pedals & switches

CC64–69. Sustain, portamento on/off, sostenuto, soft pedal, legato footswitch, and Hold 2. Values below 64 mean Off; 64–127 mean On. These editable bytes are sent only to MS Basic/SoundFont, and the instrument may ignore a pedal it does not implement. A CC64 lane takes over notation sustain messages; a CC66 lane takes over notation sostenuto messages on the corresponding channels while present.

Sound controllers

CC70–79. Variation, timbre, release, attack, brightness, decay, vibrato rate/depth/delay, and Sound Controller 10. A receiver can interpret or ignore them.

Effects

CC12–13, CC44–45, CC91–95. Effect control and effect depths such as reverb or chorus. These generic lanes do not configure MillerScore's mixer effect chain or sends.

Data entry — protected

CC6, CC38, CC96, CC97. Data Entry MSB/LSB and increment/decrement act on a selected parameter. Standalone values can modify unintended settings. Editing is blocked.

RPN/NRPN selection — protected

CC98–101. Registered and non-registered parameter selectors form ordered stateful sequences with data entry. This release does not provide a semantic RPN/NRPN sequence editor. Editing is blocked.

Undefined/reserved

Numbers without a defined function are shown by CC number. A device may assign its own meaning. Editable storage does not imply a standardized sound or receiver support; consult the receiver's manual.

Channel mode — protected

CC120–127. All Sound Off, Reset All Controllers, Local Control, All Notes Off, Omni Off/On, Mono On, and Poly On. They can silence notes, reset state, or change routing. Editing is blocked; these are commands, not ordinary continuous curves.

7-bit lanes & paired 14-bit data

CC0–31 are the MSB positions and CC32–63 their LSB positions in the paired controller range. When a receiver supports a defined pair, its 14-bit value is 128 × MSB + LSB, from 0 to 16383. Undefined positions do not acquire a standard meaning just because they fall in this range.

MillerScore stores paired numbered lanes as separate 0–127 values and sends each editable lane as its own 7-bit byte to MS Basic/SoundFont. Pairing metadata does not guarantee an automatic combined 14-bit control, 14-bit interpolation, or a particular receiver response. RPN/NRPN selectors CC98–101 retain paired parameter-selection metadata but remain read-only and are never sent by generic automation. CC88 is a special velocity-prefix message, not an MSB/LSB partner in this range, and is also protected. Generic DAW CC lanes are not supported in Standard MIDI File (SMF) export.

Open the complete CC0–CC127 reference

Editor defaults below describe the catalog's starting value, not a universal MIDI device reset value. All lanes store bytes 0–127; commands can have narrower semantic meanings shown below. “Protected” blocks mutation and those 20 lanes are never sent. “Editable” means project storage and dispatch during main playback to MS Basic/SoundFont only; the instrument can ignore individual controllers. No generic routing is provided to Muse Sounds, VST3, or external MIDI output, or in SMF export.

06 · Choose a playback source

SoundFont, VST3 & optional Muse Sounds

Select an instrument track in DAW view. The track inspector's Sound selector groups installed resources by backend. This assignment is shared with the mixer. Wait for scanning or switching to finish, then audition a short phrase.

SoundFonts (.sf2)

  1. Place a SoundFont you are licensed to use in a folder listed under Preferences > Folders > SoundFonts. The default user folder is Documents\MillerScore\SoundFonts for a release profile.
  2. Restart if the new SoundFont is not listed, then refresh the sound list.
  3. Choose a preset under SoundFonts for the selected instrument. Test playback, volume, and the note range.

A SoundFont may contain many presets; choosing a file does not guarantee a suitable instrument or percussion mapping. Missing custom SoundFonts need to be installed again on another computer.

Compatible VST3 instruments & effects

  1. Use the plug-in vendor's installer to install a Windows 64-bit VST3 plug-in. Install its required sample content separately.
  2. Check the VST3 search folders in Preferences > Folders, then use the rescan control after adding or updating a plug-in.
  3. Choose an instrument in the track's VST3 sound group. Use the mixer for supported VST3 effects.
  4. Open the plug-in's editor where available, load its patch, and test save/reopen with a project copy.

Compatibility is specific to the plug-in and version. Registration success does not prove playback stability. A notation extension in the Plugins folder is different from a VST3 audio plug-in. Vendor activation, licensing, and network services belong to that vendor.

Muse Sounds is optional

Muse Sounds sound libraries and the MuseSampler runtime are distributed separately by their provider. MillerScore does not bundle proprietary Muse Sounds content. Use the provider's installation instructions and terms if you choose to install it.

When a compatible runtime and installed libraries are found, available resources appear under Muse Sounds. If none appear, use a SoundFont or compatible VST3 source. Absence of this optional component is not evidence that MillerScore was installed incorrectly.

New-project sound-profile selection can fall back to the basic SoundFont profile when Muse Sounds is unavailable. Do not assume every previously saved Muse Sounds assignment automatically falls back on another computer. A missing assignment is kept and shown as unavailable; choose an installed source explicitly when needed.

Current integration limits. Independent note velocity is unavailable for Muse Sounds. Generic DAW CC automation is supported only by MS Basic/SoundFont and is not sent to Muse Sounds or VST3. Playback, seeking, looping, source changes, and mixer compatibility with a particular proprietary runtime still require validation on that installation.

If the sound list fails to load, use Refresh list. A missing or failed resource should be investigated before changing the saved assignment. Save a copy if you need to substitute a source for another machine.

07 · Balance your project

Mixer workflow

The mixer controls the project's playback tracks. Choose sounds, balance level and pan, and use mute or solo to isolate an instrument. DAW instrument-track controls share the existing project audio settings rather than creating a second independent mixer.

  1. Play a representative passage and set instrument levels without clipping the output.
  2. Check mute and solo before diagnosing a silent sound source.
  3. Add supported effects or adjust sends where those controls are available. Effect compatibility depends on the installed backend and plug-in.
  4. Save and reopen a project copy after making significant sound or effect changes.

Generic CC7/CC10 curves change the receiving SoundFont instrument's volume/pan during main playback; they remain separate from mixer level/pan controls. The numbered lanes retain raw 7-bit MIDI values. Effect-depth CC lanes do not automate mixer sends. Audio tracks expose their own mute and level state; do not assume every score-track mixer feature is available on imported audio tracks.

Full Read, Touch, Latch, and Write automation workflows are still incomplete. A displayed control does not establish full automation recording or identical behavior in every sound engine.

08 · Work with external audio

Audio import & recording

Import WAV, MP3, or FLAC

  1. Save the source audio in a stable folder you will keep with the project.
  2. In DAW view, choose Audio track, position the playhead, and use that track's import button. Double-clicking its audio lane also opens import.
  3. Choose a supported file. The clip is placed at the chosen musical tick; drag it to change its start position.
  4. Play the passage with the score, then save the native project.

Files are decoded into memory and referenced by their filesystem paths; they are not embedded or copied into the score archive. Clip starts follow the tempo timeline, while the source recording keeps its fixed duration. There is no claim of automatic tempo matching or time stretching.

Long files can use substantial memory. The current audio-track engine render is limited to the first 30 minutes of a track's rendered timeline; material beyond that boundary may not play. Split or shorten material and audition the full arrangement.

Before moving or sharing a project: copy its audio files as well as its score. Existing clip references may still point to the original locations. This release has no complete portable-media collection or relink workflow. Restore the original location or reimport the media at the correct tick.

Record an ASIO input

  1. Select an ASIO driver and an interface with input channels in Preferences > Audio & MIDI.
  2. Add an audio track and use its R button to arm it. Only one audio track can be armed at a time.
  3. Place the playhead at the intended start. Choose Record; the score plays while the interface input is captured.
  4. Choose Stop to finish the take. Check the clip by listening before recording another take.

Recording currently captures up to two ASIO input channels and writes 32-bit float WAV. For a saved score, takes go into a sibling <score name> Audio folder. For an unsaved score, they go into Documents\MillerScore\Recordings. Saving the score later does not automatically relocate those files.

Input selection, monitoring, and latency compensation are incomplete. Do not rely on sample-accurate overdub alignment. If a take has gaps, try a larger ASIO buffer and reduce processing load. A “Nothing was recorded” message means you should check the interface inputs and that playback actually started.

09 · Preserve your work

Saving, backups & recovery

Use File > Save for the native score project, and Save As for a separate working copy. Keep the native project alongside its external recordings and imported media. An audio export or printed score is not a complete editable project backup.

Configure Auto save in Preferences > Save & publish. Autosave is recovery assistance; continue saving normally. The optional backup-before-save setting keeps the previous disk version in the hidden .mscbackup folder next to the score, with a name such as .Example.mscz~.

After an unexpected exit

  1. Preserve the original score, its backup folder, and external media before making further changes.
  2. Restart MillerScore. If a recovery prompt offers unsaved work, inspect the recovered score and save it to a new name.
  3. Check notes, performance edits, sound assignments, and audio references. Replay a short passage.
  4. If recovery is unavailable, work from a copy of your last known-good score or backup. Keep the failed file for a private support investigation if needed.

Missing-media warning: unavailable clips are marked [Missing] and remain silent. Their file references and start positions are retained. Restore readable files at the expected locations and reopen the score. Preserve a backup of the project and media before relocating or replacing them.

Cloud-synchronized folders can add locks, offline placeholders, or delayed writes. Make sure the project and its media are available locally. A separate versioned backup protects against accidental overwrite and sync errors; autosave does not replace that backup.

10 · Diagnose one change at a time

Troubleshooting

MillerScore does not start or exits immediately

Confirm the entire ZIP was extracted and launch from its extracted folder. Keep DLLs, QML, sounds, and other shipped resources with the executable. Try a freshly extracted copy in a new writable local folder, then test without opening your previous score.

If a new copy fails too, record the version, Windows version, and exact steps. Keep the latest application and launcher logs. Check Windows Event Viewer under Windows Logs > Application for the faulting application/module. Preserve preferences before investigating corrupt settings; avoid deleting your only project or media copy.

The window is blank, clipped, or has graphics glitches

Try a normal window size and a standard Windows display scale, then restart. Check for an updated graphics driver from your device vendor. Note whether the problem affects the score, DAW, or both, and attach a redacted screenshot. A display-specific workaround needs confirmation on your device.

Playback is silent or crackles

Check the Windows output and volume, the chosen audio device, mute/solo, and the instrument sound assignment. Try a simple score with a SoundFont to isolate plug-in or optional-library issues. For crackles, try a larger audio buffer and fewer expensive instruments/effects.

If an interface was unplugged, reconnect it and reselect the device, or choose another available output. For a SoundFont instrument, also check generic CC7/CC11 automation for zero values that can attenuate or silence it. CC automation does not supply a missing sound library or repair an unavailable audio device.

A VST3 is missing, fails scanning, or causes a crash

Confirm it is a Windows 64-bit VST3, its content and activation are installed, and its folder is included in the VST3 search paths. Rescan after installation. Preserve the scan log and test a SoundFont assignment in a project copy.

If the problem began after adding a plug-in, isolate that plug-in using its vendor's normal repair/uninstall workflow. Record its name and version privately. Do not upload licensed binaries, activation files, or sample content to an issue.

Muse Sounds does not appear or a sound is unavailable

The component is optional and installed separately. Confirm the provider's installation completed and a compatible MuseSampler runtime and sound library are present. Restart MillerScore and refresh the sound list. Choose an installed SoundFont or VST3 when you need to continue.

A missing assignment can be retained in the project. Use a separate copy when substituting a sound, and audition the replacement. Do not treat an absent optional library as an application-installation failure.

An audio clip is missing or a recording is empty

Restore imported media at its original path or reimport it at the original start tick. Preserve the original project before saving after a missing-media warning. For recording, confirm an audio track is armed, the ASIO device exposes inputs, and playback starts.

Recordings are separate WAV files. Check the score's sibling Audio folder or the unsaved-project Recordings folder. A failed or interrupted take is not guaranteed recoverable.

The update check fails or the itch app does not open

Check your connection, proxy/firewall rules, and whether GitHub is reachable. Missing release metadata, HTTP 404, rate limits, or malformed responses can prevent a check. That result does not establish whether you have the newest store build.

Open your itch library or the official MillerScore download page directly. Sign in with the account that has access. A source-only GitHub release has no bundled Windows installer. If no itch handler is registered, use the browser download path; do not enter itch credentials into MillerScore.

A controller curve saves but makes no audible change

Check whether it is a numbered generic CC lane or a dedicated channel/note control. Generic CC automation requires a confirmed MS Basic/SoundFont assignment and main score playback; note previews do not apply it. SoundFonts can ignore controllers, especially undefined numbers or LSB partners. Muse Sounds, VST3, and external MIDI output do not receive generic lanes. Protected bank, note-state, data-entry, RPN/NRPN, and channel-mode controllers are never sent. See the controller support section before changing your sound source.

Report a reproducible problem through the MillerScore issue tracker. Include the application version, concise steps, expected and actual behavior, the sound backend, and relevant redacted log lines. Use a small score you are allowed to share.

11 · Keep reports private

Logs, crash reports & privacy

For the standard Windows release profile, the application data root is normally %LOCALAPPDATA%\MillerScore\MillerScore. Open that location in File Explorer. Development builds may use a separate MillerScoreDevelopment profile; portable configurations can use a different root.

  • Application logs: the logs folder, with timestamped MillerScore log files. Older matching logs are periodically removed.
  • Plug-in scan logs: logs\audiopluginregistration_YYMMDD.log, when plug-in registration has run.
  • Crashpad database/dumps: logs\dumps, when the packaged build includes and starts crash handling. A crash may not produce a dump.
  • Before the application starts: the launcher may show a Windows error dialog instead of creating an application log. Record its error number and redact any personal path before sharing a screenshot.

Crash-report uploads are disabled by default, and this release has no crash-upload server configured. Logs can include score names, media and plug-in paths, device details, and user-folder names. Crash dumps can contain process memory and private content. Review and redact diagnostic files before sharing; do not post an unreviewed diagnostic archive or dump to a public issue.

Update checks contact GitHub's public Releases API. GitHub receives ordinary request information, including the network address and request headers. Disable automatic checks in Preferences > General > Updates if you do not want automatic requests.

Scores, audio references, recordings, and preferences are local files. Cloud folders, publishing/sharing actions, browser links, itch.io, third-party plug-ins, and optional Muse Sounds services have their own behavior and privacy terms. Review the MillerScore privacy notice before using online features or sending reports.

13 · Know the current boundaries

Early Access limitations & changes

  • Generic CC automation is sent only to MS Basic/SoundFont during main playback, with an instrument-dependent response. The 20 protected bank-selection, parameter-state, note-state, and channel-mode controllers cannot be edited and are never sent. Muse Sounds, VST3, external MIDI output, and SMF export do not support these generic DAW lanes.
  • Per-note pan, release velocity, and filter controls are unavailable. Muse Sounds has no independent per-note velocity control.
  • Recording input selection, monitoring, and latency compensation are incomplete; only one audio track is armed at a time.
  • Imported audio and takes are externally referenced. Missing-media recovery, relinking, portable collection, and long-track handling have limits.
  • Full automation recording modes are incomplete. MIDI/MusicXML interchange does not promise complete DAW project fidelity.
  • Hardware, graphics, plug-in, and optional proprietary-runtime compatibility still needs wider validation.

v0.1.0 feature baseline

The Early Access series introduces connected Score and DAW views, a projected piano roll with performance overrides, a complete numbered controller catalog with safety restrictions, SoundFont/VST3 sound assignment, optional separately installed Muse Sounds resources, WAV/MP3/FLAC tracks, ASIO recording, a project mixer, and GitHub-based release checks with itch.io handoff.

This is a feature summary, not a claim that every workflow or backend has passed release validation. For changes tied to a published version, read its release notes and the store's available downloads.
